# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## 역할과 작업 원칙

- 너는 **웹 게임 개발자**다. 이 저장소의 게임은 외부 툴(빌드 도구, 게임 엔진, npm 패키지, 이미지 생성기 등) 없이 **Claude Code만으로** 만든다. 그래픽은 코드로 그린다(SVG/Canvas 도트, CSS).
- 게임/페이지 디자인 작업은 **impeccable 스킬**(`/impeccable`)로 진행한다. 이미지 생성 수단이 없으므로 code-led 방식으로 빌드한다.
- 사용자는 한국어를 쓰는 초보 바이브 코더다. 설명은 한국어로 쉽게 한다.
- **보안 안내는 필수다.** 작업 중에 보안 취약점이 있거나 생길 수 있다고 판단되면, 요청받지 않았더라도 반드시 사용자에게 알린다. 코드, 실행 명령, 설정, 외부 리소스가 모두 해당된다(예: 서버를 `127.0.0.1` 없이 열기, `innerHTML`에 외부 입력 넣기, CDN `@latest`에 SRI 없음, 개인정보 노출). 알릴 때는 무엇이 위험한지, 어떤 일이 생길 수 있는지, 어떻게 고치는지를 초보자도 이해할 수 있게 쉬운 말로 설명한다.
- **작업 보고는 한국어로 한다.** 작업을 마치고 결과를 정리해 보고할 때는 영어 용어, 도구 출력, 에러 메시지, 경고 문구를 한국어로 풀어서 전달한다. 원문이 꼭 필요하면(명령어, 파일명, 코드, 검색할 에러 원문) 원문을 그대로 두고 옆에 한국어 설명을 붙인다.
- **이미 만든 것은 지우지 않는다.** 새 지시가 기존 구현과 충돌하는지 먼저 살펴서, 분명하면 고치고 애매하면 사용자에게 어떻게 할지 묻는다(사용자 요청, 2026-10-16). "껍데기만"은 게임 바깥 UI(안내판, 설정, 버튼 등)는 만들되 게임 규칙·루프는 아직 만들지 말라는 뜻이다.
- **이 CLAUDE.md는 살아 있는 문서다.** 브랜드/폰트 확정, 새 페이지·게임 추가, 반복되는 사용자 피드백, 새 제약 등 중요한 내용이 생기면 사용자에게 묻지 않고 즉시 이 파일을 갱신한다.

## 실행 / 확인

빌드·린트·테스트 없음. 페이지마다 HTML 파일 하나에 CSS/JS가 다 들어 있다.

- 파일을 브라우저로 바로 열면 된다(`start index.html`).
- 로컬 서버가 필요하면 반드시 내 PC 전용으로 바인딩한다: `python -m http.server 8000 --bind 127.0.0.1` → http://127.0.0.1:8000
  - **서버는 마음대로 켜지 않는다.** 필요해 보이면 먼저 사용자에게 켜도 되는지 묻고, 허락받은 뒤에 켠다(사용자 요청, 2026-10-08).
- `file://`로 열면 Chrome은 각 파일을 서로 다른 출처로 취급한다. 프레임 간 접근, `document.referrer` 같은 것이 막히거나 비어 있을 수 있다(`errors/error1.PNG` 참고). 이런 동작은 로컬 서버에서 확인한다.
- 화면 캡처 확인은 헤드리스 Edge로 한다:
  `"C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" --headless=new --screenshot=out.png --window-size=1440,900 file:///C:/Users/User/my-game/arcade.html`
  - 모바일(390px)은 최소 창 폭 제한이 있어서, 390px `<iframe>`으로 감싼 래퍼 HTML을 캡처한다.
  - 캡처용 임시 파일은 저장소 밖(job tmp 폴더)에 둔다.
- impeccable 디자인 훅이 켜져 있다. 경고가 의도된 디자인이면 `impeccable hooks ignore-value <rule> "*" --file <file> --reason "..."`로 해당 파일에만 예외를 기록한다(`.impeccable/config.json`). 사용자가 요청하지 않으면 finish-reviewer 에이전트는 돌리지 않는다.

## 브랜드 (게임 작업 기준)

**이온음료 계열 컬러.** 시원하고 청량하고 깨끗한 느낌을 준다. 아래 토큰을 `:root`에 정의하고 상황에 맞게 골라 쓴다.

| 토큰 | 값 | 용도 |
|---|---|---|
| `--ion-blue` | `#0a5fd1` | 메인 브랜드, 주요 버튼, 제목 |
| `--ion-deep` | `#06357a` | 텍스트/외곽선, 어두운 배경 |
| `--ion-sky` | `#5cc8f5` | 보조색, 하이라이트, 하늘 |
| `--ion-ice` | `#e8f6ff` | 밝은 배경, 패널 |
| `--ion-white` | `#ffffff` | 캔/라벨 흰색, 텍스트 반전 |
| `--ion-lime` | `#c6f04a` | 포인트 강조(점수, 콤보, 보상). 조금만 쓴다 |
| `--ion-fizz` | `#9ee8ff` | 탄산 거품, 반짝이 이펙트 |

- 경고나 게임 오버 상태에만 따뜻한 색(예: `#ff5a6e`)을 잠깐 쓴다. 그 외에는 파랑·흰색 계열을 유지한다.
- **폰트(임시)**: 게임 UI와 제목은 **Galmuri11**(한글 도트 폰트), 긴 본문은 Pretendard를 쓴다. 더 맞는 폰트가 정해지면 이 줄을 갱신한다.
  - `https://cdn.jsdelivr.net/npm/galmuri@2.40.3/dist/galmuri.css`
  - `https://cdn.jsdelivr.net/npm/pretendard@1.3.9/dist/web/static/pretendard.css`
  - 외부 CDN 주소는 항상 정확한 버전 번호로 고정한다. `@latest`는 쓰지 않는다(보안, 2026-10-13).
- 기존 소개 페이지(`index.html` 크림색 다마고치, `index2.html`)는 각자의 테마를 유지한다. 사용자가 요청할 때만 이온 컬러로 바꾼다.

## 구조

- `index.html`: 메인 자기소개 페이지(호성고치 다마고치 디자인). 소개 섹션의 무지개 "오락실 가기" 버튼이 `arcade.html`로 연결된다.
- `index2.html`: 닉네임 "걸음마(걸음의 악마)" 유머 페이지.
- `arcade.html`: 오락실. 한 파일 안에 해시로 화면을 나눈다. `#`(없음) = 게임 목록(로비), `#yacht`. (달걀 점프는 `runner.html`로 분리됨, 2026-10-20)
  - 각 화면은 `<section data-view="...">`이고, `route()`가 `hashchange`에 맞춰 보여 줄 화면을 바꾼다.
  - **새 게임 추가 순서:**
    1. `data-view` 섹션을 추가한다.
    2. 로비 `.row`에 게임기(`a.slot`)를 추가한다.
    3. `route()`의 제목 맵을 추가한다.
    4. 키보드 핸들러를 `view` 조건으로 묶는다.
  - **게임기 디자인 규칙:**
    - 어두운 방 배경, 컬러 몸통(`--c` / `--c-deep` / `--c-ink`, `.sky`·`.off`처럼 클래스로 교체), 마키(게임 이름판), 어두운 화면, 노란 둥근 버튼(`.push`).
    - 새 게임은 이 구조를 계승하고 몸통 색만 바꾼다.
  - **요트 다이스:**
    - 주사위는 달걀 껍질 색 16×16 도트이고, 1의 눈은 빨간색이다.
    - 12칸 표준 규칙: 숫자 6칸, 초이스, 포카인드(전부 합), 풀하우스(전부 합), 스몰 15, 라지 30, 요트 50. 숫자 칸 합이 63 이상이면 +35.
    - 한 턴에 3번까지 굴린다. 키보드는 Space가 굴리기, 1~5가 킵이다.
  - 최고 기록은 `localStorage`의 `egg-jump-best`, `yacht-best`, `rps-best-streak`(rps.html이 저장, 로비 받침에 표시), `mole-best`(mole.html이 저장, 로비 받침에 표시), `brick-best`(brick.html이 저장, 로비 받침에 표시)에 저장하고, 읽기/쓰기는 `store` 헬퍼(try/catch)로 한다.
  - 뒤로가기 버튼:
    - 게임 화면에서는 "게임 목록"으로 돌아간다.
    - 목록에서는 index에서 왔으면 `history.back()`, 아니면 `index.html` 링크로 이동한다.
  - 로비 미리보기의 달걀·김밥(`EGG`, `KIMBAP`)은 `runner.html`과 같은 설계도가 arcade.html에도 복사돼 있다. 고칠 때 둘 다 고친다.
  - 로비 게임기 순서: 달걀 점프(분홍, `runner.html`로 링크) → 요트 다이스(`.sky`) → 가위바위보(`.ice`, `rps.html`로 링크) → 두더지 잡기(`.bunny`, `mole.html`로 링크) → 벽돌 깨기(`.blue`, `brick.html`로 링크) → "??? 준비 중"(`.off`, 링크 없음). 넓은 화면에서는 한 줄에 3대씩 놓인다.
- `runner.html`: 달걀 점프. 원래 arcade.html 안의 `#jump` 화면이었는데 **별도 파일로 분리**했다(사용자 요청, 2026-10-20). 게임 목록 버튼은 `arcade.html`로 간다.
  - 어두운 방 + 분홍 게임기(`--c #ff7a9a` / `--c-deep #e2577c` / `--c-ink #6b1f3c`), 마키 "달걀 점프", 노란 둥근 점프 버튼(`.push`).
  - **바깥 배경**(사용자 선택, 2026-10-20): 화면에 고정된 `.outside`(`z-index -1`)가 게임 속 하늘(`skyAt`)을 방 색 `#171a2e`에 78% 섞어(`OUT_DARK`) 늘 어두운 세로 그라데이션으로 따라간다(`updateOutside`, `draw()`마다 부르지만 색이 바뀔 때만 `--out-top/--out-mid/--out-bot`을 고침). 그래서 밤→새벽→낮→저녁이 바깥에도 은은하게 보이고, 분홍 게임기는 계속 돋보인다. 그 위로 게임 속 깃털 그림(`SPR.feather.toDataURL()`)이 옅게(투명도 0.14~0.26) 9개 아주 느리게 떨어지며 좌우로 살랑인다(`.drift` 떨어지기 30~46초 + 안쪽 `i`가 흔들기, 크기 15~30px). 움직임 줄이기면 깃털은 제자리에 멈춘다.
  - **바깥으로 이어지는 게임 세계**(사용자 요청 2026-10-20): `.outside` 맨 뒤 캔버스(`.world`, `drawOutsideWorld`, 매 프레임 `draw()`에서)가 게임 화면이 실제로 보이는 위치·배율(`getBoundingClientRect`)을 재서, 같은 배율로 화면 밖 좌표까지 먼 산·건물(`drawSkyline`)·지평선 아래 땅·무지개 길(`drawRoad`)을 그린다. 게임 화면과 같은 함수·같은 `dist`를 쓰므로 지평선 높이와 흐르는 속도가 맞아, 게임 화면이 게임기 양옆으로 늘어난 것처럼 보인다. 바깥은 조금 옅게(`OUT_WORLD 0.75`, 길 0.55). 크기는 `innerWidth`가 아니라 바깥 캔버스 자신의 상자로 잰다(스크롤바·휴대폰 주소창 때문에 어긋나지 않게). 헤드리스 캡처는 창 크기가 나중에 바뀌므로, 테스트에서는 resize 때 `draw()`를 다시 불러야 맞게 찍힌다.
  - `<canvas id="game">`(480×**232**: 원래 200 + 땅 높이 32만큼 늘림, 늘어난 땅에 깃털 스티커) + `requestAnimationFrame` 루프. 바닥선 `GROUND`는 168 그대로. 스프라이트는 모두 `sprite()`로 그린 캔버스(`SPR`). 숫자는 스크립트 위 "숫자" 묶음에 모여 있다.
  - 최고 기록 `egg-jump-best`(거리 m, 로비 받침에 표시). 다른 탭·앱으로 가면 하던 판을 접는다(`pauseJump`).
  - **고도화**(사용자 선택 4묶음 전부, 2026-10-20). `state`: ready → playing → ending(슬로모션) → over(결과판).
    - **손맛:** 가변 점프(누르는 동안 최대 약 93px, 일찍 떼면 위로 가는 속도 절반 `CUT` → 약 35px), 선입력 0.12초(`BUFFER`)·코요테 0.08초(`COYOTE`). 입력은 `pressJump`/`releaseJump`/`setDuck` 하나로 모은다(스페이스·↑·↓ 키, 캔버스·점프·숙이기 버튼 pointerdown/up). 착지하면 0.1초 납작 + 흙먼지. 부딪히면 타격 별 + 게임기 부르르(`.cabinet.rumble`) + 1초 동안 1/8 속도 슬로모션(`SLOWMO`, 벽돌 깨기와 같은 값) 뒤 결과판. 슬로모션 중엔 입력을 안 받는다.
    - **숙이기:** ↓ 키 / "숙이기" 버튼(휴대폰도 보임). 땅에서 누르면 달걀을 낮고 넓게 그린다(`DUCK` 14×7칸 크기, 맵은 그대로). 공중에서 누르면 빨리 떨어진다(`FAST_FALL`).
    - **장애물 패턴**(`spawn`, 단계가 오를수록 섞임): 김밥·닭강정 하나(처음부터) → 2단 김밥(길게 눌러야 넘음)·낮은 떡꼬치(숙이거나 높이 뛰어 피함)·닭강정 2연속(2단계+) → 높은 떡꼬치(서 있으면 머리 위로 지나가고, 뛰면 부딪힘)·닭강정 3연속(3단계+) → 김밥 뒤 바로 떡꼬치(4단계+). 닭강정 연속 간격은 `max(140, 속도×0.55)`라 짧은 점프로 사이에 내려앉을 수 있다. 다음 패턴까지 간격은 거리로 정한다: `max(230, 속도×0.7)` + 0~190px(빠를수록 길게 뛴 점프가 내려앉고 다시 뛸 틈). 김밥 뒤 떡꼬치(combo) 사이도 `max(230, 속도×0.75)`. 자동 플레이로 최고 속도(770)에서 150초 버티는 것을 확인했다(2단 김밥은 빠를수록 일찍 뛰어야 넘는다). 떡꼬치 `SKEWER`는 새 도트(빨간 양념 떡 셋 + 꼬챙이).

  - **물리**: 받침대 기본 363px/초(300 → 330 → 363, 사용자 요청으로 두 번 10%씩 올림). **공 속도가 오른 비율만큼 받침대도 빨라진다**(`SPEED × (1 + boost)`, 공 +100%면 받침대 726px/초, 사용자 요청). 공 10px, 처음 250px/초. **받침대에 닿을 때마다 처음 속도의 +5%씩 빨라지고 최대 +100%(500px/초)**(`boost`, `BOOST_STEP`·`BOOST_MAX`, 사용자 요청 2026-10-16). 예전의 "벽돌 하나마다 +6, 최고 420" 규칙은 이 규칙과 겹쳐서 없앴다. 목숨을 잃어도 속도는 유지된다. **판이 끝나 결과판이 뜨면(게임 오버·클리어 모두) 속도가 기본값(+0%)으로 돌아가고** 계기판·가속 효과·꼬리도 꺼진다(사용자 요청). 빠른 공이 뚫지 않게 한 프레임을 4px 단위로 쪼개 움직인다(`step`). 벽·천장 반사, 받침대는 맞은 자리에 따라 최대 60도로 꺾여 튕김, 벽돌은 덜 겹친 방향으로 반사(`bounceOff`). 프레임 간격은 최대 1/30초로 자른다.
  - **혜성 꼬리**(사용자 요청, 크레이지 아케이드 '샤샤샥'): 공 속도 +50%부터 공 뒤로 잔상 꼬리(`b.tail`, 1/60초마다 지나온 자리 하나)가 생기고 +100%까지 조금씩 길어진다(6 → 18칸, `tailLength`). 꼬리 끝일수록 작고 옅으며 파랑 → 하늘 → 크림. 워프로 순간이동하면 꼬리를 끊는다. 특수 벽돌 깨짐 잔상(`trail`)과는 따로다.
  - 결과판이 뜨면 '다시 하기'에 자동으로 포커스가 가지만(Enter로 바로 재시작), 점선 포커스 테두리는 그리지 않는다(`#againBtn:focus-visible { outline: none }`, 어설퍼 보인다는 사용자 요청).
  - **끝날 때 슬로모션**(사용자 요청): 마지막 목숨을 잃거나 벽돌을 다 깨면 바로 멈추지 않고 `phase = 'ending'`으로 1초(실제 시간) 동안 1/8 속도(`SLOWMO`, 처음 1/4였다가 사용자 요청으로 2배 더 느리게)로 계속 움직인 뒤 결과판(`showResult`). 이 동안 공이 바닥으로 떨어져도 그냥 사라지고(목숨·게임 오버 없음), 아이템은 받아지지 않고, 스페이스바 발사도 안 된다.
  - **공은 여러 개**(`balls` 배열, 최대 12): 바닥으로 떨어진 공은 사라지고, **화면의 공이 모두 사라졌을 때만** 목숨 -1. 목숨을 잃으면 공 1개(받침대에 붙음)·받침대 기본 크기로 돌아가고 떨어지던 아이템은 사라진다.
  - **속도 계기판** `#gauge`: HUD 가운데 목숨 아래, 두더지 잡기 속도 표시와 같은 남색 알약. "속도" + 도트 화살표 10칸(한 칸 = +10%, 끝 3칸은 주황) + "+N%". 최대면 화살표가 깜빡이고 숫자가 주황(`.max`).
  - 발사 안내 "스페이스바를 눌러 발사!"(터치 기기는 "받침대 근처를 터치해서 발사!")는 캔버스 위에 올린 HTML 글자 `#launchHint`다. 캔버스 안에 쓴 글씨는 작은 화면에서 줄여 보이며 뭉개지기 때문. 아이템 이름·안내도 같은 이유로 HTML 글자 `boardFloat()`(`.bfloat`)로 띄운다.
  - **점수**: 위 줄일수록 높다(`(줄 수 - 줄 번호) × 10`, 5줄이면 맨 위 50 ~ 맨 아래 10). 강철은 ×2, 번개는 ×3. 보통 벽돌은 깨지면 색 조각 6개가 튄다(`bits`).
  - **벽돌 종류**(사용자 요청 2026-10-16, `buildBricks`):
    - **맨 윗줄은 전부 2번 벽돌**(`top`, 단단해 보이는 어두운 금속 `#4f5b74` + 가는 반사줄·빛 조각, 사용자 요청. 금은 밝은 색으로 찍는다): 1번 맞으면 바로 '금 잔뜩', 2번째에 깨진다. 아래 특수 벽돌과 같은 특징(아이템 50%, 깨짐 이펙트).
    - **강철 3번 벽돌**(`tough`, 은빛 `#aab8d4` + 네 귀퉁이 리벳): 맨 윗줄을 뺀 줄에서 10%. 1번 맞으면 '금 살짝', 2번 '금 잔뜩', 3번째 깨짐. 금은 벽돌마다 미리 만든 지그재그(`makeCracks`)를 짙은 도트로 찍는다.
    - **번개 벽돌**(`max`, 남색 `#24306e` + 노란 테두리·번개): 맨 윗줄을 뺀 줄에서 10%. **공이 최고 속도(+100%)일 때만 깨진다.** 아니면 튕기고 번쩍이며 "최고 속도로 쳐야 깨져요!"(1초에 한 번). 최고 속도일 땐 번개가 깜빡여 '지금 깰 수 있음'을 알린다. 깨지면 게임기 부르르(`.cabinet.rumble`) + 깨짐 이펙트.
    - **깨질 때 화면 멈춤**(`HITSTOP`, 사용자 요청): 2번 벽돌 0.05초 · 강철 0.05초 · 번개 0.1초(`freeze`). (0.1/0.15/0.2 → 강철을 2번과 같게 → 모두 절반, 사용자 요청) 보통 벽돌은 멈추지 않는다.
    - 맨 윗줄은 특수 벽돌이 나오지 않으므로 줄을 1줄로 고르면 특수 벽돌이 없다(전부 2번 벽돌).
    - **깨짐 이펙트**(`breakThrough`, 특수 벽돌이 깨질 때): 공은 **기본 벽돌처럼 튕겨 나온다**(처음엔 뚫고 지나가는 '돌파'였는데 사용자 요청으로 바꿈). 조각 12개가 공이 들어오던 방향으로 쏟아지고, 벽돌 테두리 충격파(`fx` shock)와 공 잔상(`pierce` 0.25초, `trail`)은 그대로 남는다.
  - **아이템**(특수 벽돌이 깨질 때 50%, 24×12 캡슐이 110px/초로 떨어짐, 받침대로 받으면 적용): 속도+(노랑, +20%) · 속도−(회청, −20%, 처음 속도 아래로는 안 내려감) · 공 3개(라임, 날고 있는 공 하나를 ±25도로 갈라 2개 추가) · 받침대+(하늘, 기본 폭의 130%) · 받침대−(분홍, 70%). 받침대 크기는 겹쳐 쌓이지 않고 바뀌며 목숨을 잃을 때까지 유지. 받으면 받침대 위에 이름이 뜬다.
  - **워프**(사용자 요청): 좌우 벽에 파란 입구 하나씩(4px 두께 × 26px 띠, 안쪽으로 흐르는 밝은 점), 윗벽에 빨간 출구 하나. 공이 입구에 닿으면 출구에서 아래쪽(±30도)으로 같은 속도로 나온다(0.3초 동안 재진입 막음). 받침대에 2번 닿을 때마다(`paddleHits`) 세 개 모두 무작위 자리로 옮긴다.
  - 게임기 아래 범례(`.legend`): 특수 벽돌 3종과 아이템 5종을 게임과 같은 그리기 함수로 작은 캔버스에 그려서 보여 준다(`iconCanvas`).
  - 헤드리스 Edge에서는 requestAnimationFrame이 거의 돌지 않는다. 동작 테스트는 `update(1/60)`을 직접 반복 호출해서 한다.
  - 어두운 방 + 진한 이온 파랑 `.blue` 게임기(`--c #0a5fd1` / `--c-deep #5cc8f5` / `--c-ink #06357a`), 탄산 방울 장식, 마키 "벽돌 깨기!"(사각 마키 + 깜빡이는 전구).
  - 화면: HUD(점수 · 목숨 도트 하트 5개 `#lives i`(처음 3개였다가 사용자 요청으로 5개), 잃으면 `.lost` · 최고) → `<canvas id="board">` 480×360 → 시작 안내판(`#startPanel`, 달걀 + 시작 버튼) / 결과 안내판(`#endPanel`, "Game Over!" + 최종 점수 + 다시 하기, 처음엔 숨김). 아래에 조작 안내. **받침대는 키보드 ← → 방향키로만 움직인다**(마우스로 끌기·화면 터치로 끌기는 넣지 않는다, 사용자 요청 2026-10-16).
  - **휴대폰용 좌우 버튼**(사용자 요청): 게임 화면 아래 큰 노란 ◀ ▶ 버튼 `.pad`(높이 72px). 터치 기기(`(hover: none) and (pointer: coarse)`)에서만 보이고, 그때 안내 문구도 버튼 안내로 바뀐다. 누르고 있는 동안 방향키와 똑같이 동작한다.
    - 입력 상태는 `move.left`/`move.right` 하나로 모은다: 키보드 keydown/keyup과 버튼 pointerdown/pointerup·cancel이 `hold(dir, on)`으로 같은 값을 바꾸고, 키보드를 눌러도 버튼이 눌린 모양(`.held`)이 된다. 게임 루프는 이 값만 읽으면 된다. 숫자 입력 칸 안의 ← →는 글자 커서용이라 가로채지 않는다. 창을 벗어나면 눌림을 모두 푼다.
  - 시작 전 캔버스에는 고른 배치를 그린다(`drawPreview`): 벽돌 5줄×10칸(맨 윗줄 어두운 금속, 나머지 하늘·거품·얼음·흰색, 윗면 빛·아랫면 그늘), 하늘색 받침대, 달걀 껍질 색 공.
  - **벽돌 개수 고르기**(시작 안내판, 사용자 요청): '줄'(1~5, 한 자리 칸)과 '개수'(줄당 6~10, 10 때문에 두 자리 칸) 숫자 칸 + 좌우 도트 화살표 버튼(끝 값에서 잠김) + 칸 아래 "최소 · 최대" 안내. 직접 입력은 범위 안이면 바로 반영, 밖이면 빨간 테두리 후 칸을 벗어날 때 가까운 값으로 맞춤. 칸 안에서 ↑↓도 1씩. 값은 `layout.rows`/`layout.cols`에 담기고(`LIMITS`, **처음 값은 최소치 1줄 × 6개**, 사용자 요청), 바뀔 때마다 `drawPreview()`가 뒤의 벽돌을 다시 그린다.
    - 벽돌 가로 폭은 늘 440px 안에 맞춘다(개수가 적으면 벽돌이 넓어짐). 줄 색은 위에서부터 `ROWS` 순서.

### 공통 도트 렌더링 패턴

도트 그래픽은 문자열 맵 + 팔레트로 그린다. 새 스프라이트도 이 방식을 따른다.

- SVG: `pix(map, pal, px, outline)` 함수로 그린다(index.html).
- Canvas: `sprite()` 함수로 그린다(runner.html).
- 맵 예: `['..ww..', '.wwww.']`. 글자 하나가 팔레트 색 하나이고 `.`는 투명이다. 외곽선 1px은 자동으로 생긴다.
- 애니메이션은 `steps()`로 끊어서 도트 느낌을 낸다. `prefers-reduced-motion`이면 애니메이션을 끈다.

## 고정 제약 (바꾸지 말 것)

- **달걀 도트 캐릭터 디자인은 고정이다.** 10×12 맵, 팔레트 `{w:'#f3efe4', s:'#c9c0aa', e:'#151515', m:'#151515', b:'#e07a6f'}`, 외곽선 `#1d2236`.
- index.html의 달걀 5개와 대사:
  - 대사: '반가웡!', '안녕하세요!', '어서 오세요!', '세상에서 가장 가난한 왕은?', '최저임금'
  - 달걀은 접속할 때마다 섹션에 랜덤으로 배치된다.
  - 아재개그 질문은 항상 답보다 위에 나와야 한다. 고른 위치를 DOM 순서로 정렬한 뒤 질문 인덱스 < 답 인덱스로 고른다.
- index.html 섹션 순서: 소개 → 노래 감상 → 장거리 걷기 → 오늘의 TMI → 마무리.
- 본문은 도트 폰트로 쓰지 않는다. 도트 폰트는 제목, 라벨, 게임 UI에만 쓴다.
- 좋아하는 노래·걷는 경로 같은 개인 정보는 지어내지 않는다.
