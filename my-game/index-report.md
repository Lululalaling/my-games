## 2. 뼈대 (HTML)

**HTML은 "여기에 제목, 여기에 문단, 여기에 버튼" 하고 칸을 나누는 역할**이에요. `<태그>내용</태그>` 모양으로 씁니다.

### 머리 부분 `<head>` (1~9줄): 눈에 안 보이는 설정
- `<meta charset="utf-8">`: 한글이 깨지지 않게 하는 설정
- `<meta name="viewport">`: 휴대폰 화면 크기에 맞추는 설정
- `<title>김호성 소개</title>`: 브라우저 탭에 뜨는 제목
- `<link rel="icon">`: 탭에 보이는 작은 달걀 아이콘
- `<link rel="stylesheet">` 2줄: 인터넷에서 글꼴 두 개(도트 글꼴 Galmuri, 본문 글꼴 Pretendard)를 불러옴

### 몸통 부분 `<body>` (428~517줄): 화면에 보이는 내용
| 줄 | 태그 | 내용 |
|---|---|---|
| 431~447 | `<aside>` | 왼쪽 분홍 다마고치 기기 (LCD 화면, 메뉴 아이콘, A·B·C 버튼) |
| 450~455 | `<section id="intro">` | 첫 화면: 환영 말풍선, 큰 이름 "김호성", 인사말 |
| 457~466 | `<section id="about">` | 소개 표 (이름·별명·취미·TMI) |
| 468~479 | `<section id="music">` | 노래 감상 |
| 481~493 | `<section id="walk">` | 장거리 걷기 |
| 495~504 | `<section id="lunch">` | 오늘의 TMI (스팸 김밥, 닭강정) |
| 506~510 | `<section id="outro">` | 마무리 문장 |
| 514~517 | `<footer>` | 맨 아래 저작권 문구와 현재 시간 |

> 💡 달걀 캐릭터와 카운트 버튼은 HTML에 직접 적혀 있지 않아요. 페이지가 열릴 때 **JS가 만들어서 끼워 넣어요.** 그래서 새로고침할 때마다 위치가 달라져요.

## 3. 꾸미기 (CSS)

**CSS는 "이 칸은 분홍색, 글자는 12px, 왼쪽에 고정" 같은 모양 규칙**이에요. `선택자 { 속성: 값; }` 모양으로 씁니다.

| 줄 | 무엇을 꾸미나 | 쉬운 설명 |
|---|---|---|
| 11~28 | **색 팔레트** (`:root`) | `--shell`(분홍 몸체), `--lcd`(초록 액정), `--btn`(노란 버튼) 같은 색에 이름을 붙여 둠. 색을 바꾸려면 여기만 고치면 전체가 바뀜 |
| 29~43 | 기본 설정 | 여백 초기화, 배경색, 글꼴, 글자를 드래그했을 때 색 |
| 46~60 | **화면 배치** | 왼쪽 기기 칸 + 오른쪽 본문 칸 2단 구조. 기기는 스크롤해도 따라다님(`sticky`) |
| 62~132 | **다마고치 기기** | 달걀 모양 몸체, 초록 LCD, 노란 A·B·C 버튼, 눌리는 느낌 |
| 134~169 | **LCD 속 움직임** | 달걀이 콩콩 뛰기(`hop`), 걷는 발(`blink`), 길이 흘러가기(`road`), 음표 둥실(`float`) |
| 171~271 | **본문 글자·표·메뉴판** | 이름 크기, 말풍선, 소개 표 점선, 음식 목록, 맨 아래 문구 |
| 273~323 | **달걀 친구들** | 달걀 위치, `click!` 글자, 누르면 찌그러지는 효과, 말풍선 |
| 325~407 | **10번 누르기 키** | 키보드 키캡 모양, 눌리면 6px 내려가기, reset 버튼, 실패 달걀, 폭죽 |
| 409~421 | **휴대폰 화면** | 화면 폭이 899px 이하면 1단으로 바꾸고 글자를 줄임 |
| 422~425 | **움직임 줄이기** | 기기에서 "애니메이션 줄이기"를 켠 사람에게는 움직임을 모두 끔 |

## 5. 보안 점검

### 요약

이 페이지는 **입력창, 로그인, 서버, 저장 기능이 없는 단순한 정적 페이지**라서 큰 보안 위험은 없어요. 다만 아래 5가지는 알고 있으면 좋아요.

| # | 항목 | 위험도 | 지금 당장 문제? |
|---|---|---|---|
| 1 | 로컬 서버 실행 명령이 폴더 전체를 같은 와이파이에 공개할 수 있음 | 🟠 중간 | 서버를 켤 때만 해당 |
| 2 | 외부 글꼴(CDN)을 버전 고정·검증 없이 불러옴 | 🟡 낮음 | 아니오 (미래 위험) |
| 3 | `innerHTML` 사용 | 🟢 참고 | 아니오 |
| 4 | 보안 정책(CSP) 없음 | 🟢 참고 | 아니오 |
| 5 | 개인정보 노출과 외부 접속 기록 | 🟢 참고 | 공유 범위에 따라 다름 |

### ① 🟠 로컬 서버가 폴더 전체를 같은 와이파이에 공개할 수 있음
- **어디:** 이전 대화에서 안내한 명령 `python -m http.server 8000`
- **문제:** 이 명령은 아무 설정 없이 쓰면 **같은 와이파이·공유기에 연결된 모든 기기**에서 접속할 수 있어요. 게다가 폴더 목록을 그대로 보여 줘요. 그래서 `index.html`뿐 아니라 `PRODUCT.md`, `errors` 폴더, `.impeccable` 폴더까지 **카페나 학교 와이파이의 다른 사람이 볼 수 있어요.**
- **비유:** 내 방 문만 열어 주려다가 현관문까지 열어 둔 셈이에요.
- **해결:** 항상 **내 컴퓨터에서만** 열리도록 `--bind 127.0.0.1`을 붙여 실행하세요.
  ```
  python -m http.server 8000 --bind 127.0.0.1
  ```
  (제가 이 세션에서 직접 켰던 서버는 이 옵션을 붙여 실행했어요. 다만 이전에 안내드린 명령에는 이 옵션이 빠져 있었어요. 바로잡습니다.)

### ② 🟡 외부 글꼴을 버전 고정·검증 없이 불러옴
- **어디:** 8~9줄
  ```html
  <link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/galmuri@latest/dist/galmuri.css">
  ```
- **문제:**
  - `@latest`는 "항상 최신판"이라는 뜻이에요. 글꼴 제작자가 새 버전을 올리거나, 누군가 그 패키지를 해킹해 바꿔치기하면 내 페이지 모양이 **내 허락 없이** 바뀔 수 있어요.
  - 두 링크 모두 "이 파일이 내가 확인한 그 파일이 맞는지" 검사하는 장치(SRI, `integrity` 속성)가 없어요.
  - 불러오는 것이 CSS라서 직접 프로그램을 실행할 수는 없어요. 그래서 위험도는 낮아요.
- **해결 (택 1):**
  1. 버전을 고정하고 검증값을 붙이기: `galmuri@latest` → `galmuri@2.x.x`처럼 정확한 버전 + `integrity="sha384-..."` + `crossorigin="anonymous"`
  2. 글꼴 파일을 내려받아 `my-game` 폴더에 넣고 직접 불러오기 (가장 안전, 인터넷 없어도 동작)

### ③ 🟢 `innerHTML` 사용 (지금은 안전)
- **어디:** 609, 612, 628~632, 642, 656, 668, 698~699, 727~733줄
- **설명:** `innerHTML`은 글자를 **HTML 코드로 해석해서** 화면에 넣어요. 만약 방문자가 입력한 글이나 주소창의 값이 들어가면, 나쁜 사람이 그 안에 프로그램을 몰래 넣는 공격(XSS)이 가능해져요.
- **지금 상태:** 들어가는 내용이 전부 **코드에 직접 적어 둔 고정 문구와 도트 그림**뿐이에요. 바깥에서 들어오는 값이 없어서 **현재는 공격할 방법이 없어요.**
- **앞으로 주의:** 방명록, 이름 입력, 주소창 값 읽기 같은 기능을 추가한다면 그 값은 `innerHTML` 대신 **`textContent`**로 넣으세요. `textContent`는 글자를 글자 그대로만 넣어요.

### ④ 🟢 보안 정책(CSP) 없음
- **설명:** CSP는 "이 페이지는 이 주소에서 온 파일만 쓸 수 있다"는 **출입 명단**이에요. 지금은 명단이 없어요.
- **지금 상태:** 위 ③처럼 공격이 들어올 틈이 없어서 당장 필요하지는 않아요. 나중에 인터넷에 정식으로 올리거나 입력 기능을 추가하면 넣는 걸 추천해요.
  ```html
  <meta http-equiv="Content-Security-Policy"
        content="default-src 'self'; style-src 'self' 'unsafe-inline' https://cdn.jsdelivr.net; font-src https://cdn.jsdelivr.net; img-src 'self' data:; script-src 'self' 'unsafe-inline'">
  ```
  (이 페이지는 스크립트가 파일 안에 들어 있어서 `'unsafe-inline'`이 필요해요. 더 엄격하게 하려면 스크립트를 별도 `.js` 파일로 분리해야 해요.)

### ⑤ 🟢 개인정보와 외부 접속 기록
- **개인정보:** 실명(김호성), 별명, 취미, 특정 날짜의 점심 메뉴가 들어 있어요. 처음 만나는 사람에게 보여 주는 용도라면 괜찮지만, **누구나 볼 수 있는 인터넷에 올리면** 모르는 사람도 보게 돼요. 공개 범위를 한 번 생각해 보세요.
- **외부 접속 기록:** 페이지를 열 때마다 글꼴을 `cdn.jsdelivr.net`에서 받아 와요. 그래서 방문자의 IP 주소가 그 회사 서버에 남아요. 일반적인 일이지만, 신경 쓰인다면 ②-2처럼 글꼴을 직접 넣으면 사라져요.

### 문제없음을 확인한 항목
- 비밀번호, API 키, 개인 토큰 같은 **비밀 정보: 없음**
- 쿠키, 브라우저 저장소(localStorage) **사용: 없음**
- 입력창, 폼, 서버 전송 **기능: 없음**
- 다른 사이트로 데이터를 보내는 **코드: 없음** (글꼴 다운로드 제외)
- `eval()`처럼 문자열을 코드로 실행하는 **위험 함수: 없음**

## 6. 결론

- `index.html`은 **뼈대(HTML) + 꾸미기(CSS) + 동작(JS)**이 한 파일에 담긴 단순한 자기소개 페이지예요.
- 보안상 **가장 먼저 챙길 것은 ① 로컬 서버를 켤 때 `--bind 127.0.0.1` 붙이기**예요.
- 나머지(②~⑤)는 지금 당장 위험하지 않아요. 페이지를 인터넷에 정식으로 올리거나 입력 기능을 추가할 때 함께 정리하면 돼요.
